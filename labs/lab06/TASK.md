# ЛР6. Бесконтактная оплата

Вариант: **Card**.

## Что дано

Поля `contactless_enabled` и `context.contactless` уже предусмотрены. Новое правило пока не реализовано. Новая редакция также требует сочетать расширение с существующим поведением. Каркасы дополнительных типов даны; основной алгоритм сервиса уже готов.

## Задание

### Шаг 1. Завершите предметное расширение

Добавьте `ContactlessUsageRule`. Оно возвращает `CONTACTLESS_DISABLED` только при сочетании `context.contactless=True` и `card.contactless_enabled=False`.

Подключите правило в сборке без изменения `CardService.check()`. Лимиты суммы относятся к другому сервису и здесь не проверяются.

### Шаг 2. Группа правил с тем же интерфейсом

Добавьте `UsageRuleGroup(rules)` как `CardUsageRule`. Сохраните `tuple(rules)`, не копируя объекты. Каждый элемент реализует `CardUsageRule`, иначе `INVALID_CONFIG`. Метод `check(entity, context)` вызывает правила по порядку, проверяет `CheckResult` (`INVALID_RESULT`) и возвращает первый отказ; последующие правила не вызываются. Пустая группа разрешает; исключения передаются наружу. Допустима группа внутри группы.

### Шаг 3. Подключите и сравните конфигурации

В сборке стандартные правила вместе с новым правилом объедините в `UsageRuleGroup`, а сервису передайте список из этой группы. Явно переданный набор не подменяйте. Проверки самого предметного объекта остаются обязательными. Изменение исходного списка не меняет группу; изменение самого правила видно, потому что объект не копируется.

### Шаг 4. Обязательная практическая часть

В `usage.py` реализуйте `ExpiryBufferRule(minimum_days)` через `CardUsageRule`. Неотрицательный целый порог (не bool); ошибка — `INVALID_CONFIG`. Если до окончания срока меньше порога, возвращайте `CARD_EXPIRING_SOON`. При сроке 30 апреля порог 3 разрешает 26 апреля, запрещает 28 апреля.

## Примеры и границы

- Бесконтактная операция при отключённой функции — отказ.
- При включённой функции бесконтактная операция разрешена.
- Обычная операция разрешена и при отключённой бесконтактной функции.
- Карта `NEW` недоступна при любом значении флага; прежние правила типа и `ONLINE` продолжают работать.

Последовательности и конфигурации дополнительно проверяются в `tests/test_progression.py`. Прочитайте ожидаемый результат каждого сценария до реализации.

Все проверки открыты: `tests/test_contract.py` и `tests/test_review_contract.py`.
